# 0.3.39 library isolation and image backup validation — 2026-10-03

Browser 0.3.39 · Native plugin 0.5.7 (unchanged). Local release; GitHub publication awaits review of the bilingual release notes.

## Fixes

- Drafts retain their library/target identity and a separate per-library storage slot. Opening a bound draft does not adopt an unrelated default library. Dirty legacy drafts without identity require an explicit save before native writes resume.
- Backup manifests include both pending and already-saved images, captions, dimensions and native mappings. Existing native images can be cached through the current image endpoint. Cached saved images remain available for local backup while Zotero is offline.
- History rotation retains bytes referenced by newer image backups. Legacy HTML-only records can recover retained bytes and historical attachment identities. Missing native attachments are reimported and paragraph references rebound.
- Restoring an older version excludes later pending images from its next save. Those images are retained in a separate recovery version before removal from the pending queue.
- Only an explicit missing-image response triggers recovery; transport, permission and server errors abort without clearing valid mappings or rewriting the pending queue.

## Limits

Backups cannot recreate original bytes that were already lost before this update and are no longer available from Zotero. Such a recovery must fail explicitly rather than invent image content. Legacy drafts without library identity pause automatic saving until the user confirms the destination by saving. CNKI verification pages, all publishers, all operating systems and every Zotero patch version are not covered by these results. Named publisher fallback tests remain controlled fixtures. Detailed publication-field comparison belongs to the earlier 0.3.37 run.
